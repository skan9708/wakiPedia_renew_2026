# 와인 데이터 106차 반영 기록

## 입력과 해석

- 기준: `와키_와인데이터_입력요청(10월 11일 중간값).xlsx` — 기존 와인 ID 4,800개.
- 수정본: `wakipedia_wine_data_106.xlsx`와 `wakipedia_web_import_106.json` — 대표 와인 3,507개, 원본 리뷰 4,646개, 기존 ID 4,800개의 대표 ID 대응표.
- JSON SHA-256: `7bd285b2d788a15eb4c624b623a23a8d36b33e4e8f8b1a8b5b8d5d716f36bd04`.
- 엑셀의 와인 주요 필드와 리뷰 ID·원문을 JSON과 전수 대조한 결과 불일치가 없었다.

운영 DB에는 와인 9,595개, 리뷰 4,918개가 있었다. 초기 가져오기로 만들어진 와인 약 4,795개가 한 번 더 들어가 있으며, 수정본의 4,800개 ID는 이미지와 리뷰가 주로 붙은 쪽이다. 기존 행을 통째로 지우고 수정본을 새로 가져오면 리뷰 작성자, 이미지, 좋아요, 즐겨찾기와 기존 와인 주소가 손상된다.

## 반영 규칙

1. 수정본의 대표 ID 3,507개를 목록에 표시한다. 영문명·한글명·나라·타입·품종·검색 별칭·와인 기준 맛 수치를 갱신한다.
2. 통합되거나 예전에 중복으로 가져온 행은 삭제하지 않고 목록에서 숨긴다. 대표 ID가 확실한 6,057개 행에는 기존 주소를 대표 와인으로 연결하는 값을 저장한다.
3. 기존 리뷰를 새로 만들지 않는다. 대표 와인으로 옮길 리뷰 1,419개의 와인 연결만 바꿔 작성자·원문·평점·사진·좋아요·공개 여부를 보존한다. 리뷰 총수는 4,918개로 유지한다.
4. 즐겨찾기 1개를 대표 와인으로 옮긴다. 대표 와인 이미지가 비어 있고 통합 원본에 이미지가 있는 42건은 원본 이미지를 이어받는다. 저장된 S3 파일은 삭제하지 않는다.
5. 이름만으로 서로 다른 대표 와인을 구분할 수 없는 초기 중복 행 31개는 숨긴 상태로 보존한다. 그중 ID 3의 리뷰 1개는 병 식별 근거가 없어 원본에 둔다. 나중에 확인되면 `--resolve-legacy 3:대표ID`로 이동할 수 있다.
6. 참고 평점은 리뷰 평점의 평균과 다른 자료이므로 표시 평점에 덮어쓰지 않는다. 와인 기준 맛 수치(1~5)는 리뷰가 없는 와인에서만 화면의 0~4 눈금으로 변환해 사용한다. 리뷰가 있으면 기존 리뷰 평균을 표시한다.

## 검증

운영 DB 스냅샷에 먼저 적용했다. 표시 와인 3,507개, 숨긴 와인 6,088개, 기존 주소 연결 6,057개, 리뷰 4,918개, 즐겨찾기 2개, 고아 리뷰 0개를 확인했다. 리뷰 ID·작성자·원문·평점·맛 점수·공개 여부·작성 시각은 전부 적용 전과 같았다. 이전 ID 상세 조회, 리뷰 목록, 검색 별칭, 리뷰 없는 와인의 맛 수치 표시도 확인했다. 재실행 시 리뷰·즐겨찾기 추가 이동은 0개이고 연결 6,057개가 유지됨을 확인했다.

## 운영 절차

운영 서비스 중지 → 마이그레이션 전 SQLite 백업 → 코드 반영과 Django 마이그레이션 → `import_wine_catalog` 예행 검사 → SHA-256을 지정한 적용 실행(추가 SQLite 백업 생성) → DB 건수·API·서비스 상태 확인 → 서비스 재시작 순서로 진행한다. 적용 코드는 JSON 원본의 ID 관계와 필드 범위를 검증하고, 예행 검사 결과를 먼저 출력한다.

이 문서에는 인증 정보와 사용자 개인정보를 넣지 않는다.
